# Калькулятор тренировок

Оценка расхода калорий при ходьбе и беге — на дорожке и на улице.
Нужна как независимая проверка цифр Apple Watch, которые на дорожке с уклоном сильно ошибаются.

## Запуск

Окно с пошаговым мастером (Windows, macOS, Linux):

```bash
dotnet run --project src/WorkoutCalculator.Desktop
```

Консольная версия:

```bash
dotnet run --project src/WorkoutCalculator.Cli
```

3D-модель тела по замерам (прототип, открывается в браузере):

```bash
dotnet run --project src/WorkoutCalculator.Body3D
```

Приложение поднимется на http://localhost:5256 и откроет браузер. Нужен только .NET 10 SDK:
дополнительные рабочие нагрузки (`wasm-tools`) и Node.js не нужны, three.js лежит в репозитории.

Тесты всего решения:

```bash
dotnet build WorkoutCalculator.sln
dotnet test WorkoutCalculator.sln
```

Или откройте `WorkoutCalculator.sln` в Visual Studio / Rider.
Проекты настроены на .NET 10. Body3D использует возможности Blazor из .NET 10, поэтому решению целиком нужен
.NET 10 SDK; для одних Core, Cli и Desktop можно заменить `net10.0` на `net8.0` в `Directory.Build.props`.

## Структура

| Проект | Что внутри |
|---|---|
| `WorkoutCalculator.Core` | Формулы, модели, разбор ввода, сохранение профиля. Без интерфейса. |
| `WorkoutCalculator.Desktop` | Окно на Avalonia: профиль → тренировка → параметры → часы → результат. |
| `WorkoutCalculator.Cli` | Та же логика в консоли. |
| `WorkoutCalculator.BodyModel` | Модель тела без интерфейса: антропометрия, тело MakeHuman и манекен по замерам, объём, проверки замеров, прогноз. |
| `WorkoutCalculator.Body3D` | Прототип в браузере: Blazor WebAssembly + three.js, без бэкенда. |
| `tools/WorkoutCalculator.MakeHumanImport` | Конвертер данных MakeHuman в `wwwroot/data/makehuman-hm08.bin`. Нужен только для пересборки данных. |
| `tests/WorkoutCalculator.Tests` | xUnit: эталонные расчёты калорий, манекен, тело MakeHuman, проверки, прогноз. |

## Что вводится

- **Профиль** (сохраняется между запусками, общий для окна и консоли): пол, возраст, рост, вес; необязательно — пульс покоя и VO2max.
- **Дорожка:** длительность, скорость, уклон (если они менялись по ходу — несколько отрезков), поручни, дистанция с табло для сверки.
- **Улица:** дистанция, время, набор высоты, покрытие.
- **Часы:** средний пульс, активные и общие ккал, дистанция — для сравнения.

Время можно вводить как `30`, `30,5` или `30:23`; дробные числа — через запятую или точку.

## Методы расчёта

| Метод | На чём основан | Источник |
|---|---|---|
| ACSM | скорость, уклон, время | ACSM's Guidelines for Exercise Testing and Prescription |
| Минетти | уклон, дистанция (учитывает спуск) | Minetti et al., J Appl Physiol, 2002 |
| Кейтел | пульс, вес, возраст, пол | Keytel et al., J Sports Sci, 2005 |

Итог — среднее по методам. Пульсовая оценка исключается из итога, если на долгой тренировке
она сильно выше механической (дрейф пульса) или пульс ниже 90.

Дополнительно: базовый обмен — Миффлин — Сан Жеор, максимальный пульс — Танака,
сопротивление воздуха при беге на улице — +1% уклона (Jones & Doust, 1996),
поручни — −20% к механическим методам.

Результаты — оценка, а не медицинское измерение.

## 3D-модель тела (прототип)

Тело строится по замерам — на основе MakeHuman или процедурным манекеном, — а режим гипотез показывает,
как оно может измениться за N недель при заданном питании и тренировках. Это проверка идеи,
а не финальный продукт.

### Интерфейс

- Слева 3D-вид: вращение мышью, зум колесом, кнопки «Спереди», «Сбоку», «Сзади», «Сброс камеры».
  Режимы «Сейчас», «Прогноз», «Сравнение». В сравнении текущее тело — светящийся контур поверх прогноза:
  видно, где тело уменьшится (контур снаружи) и где вырастет (контур уходит внутрь). Галочка «рядом»
  ставит модели бок о бок.
- Сверху переключатель модели «MakeHuman / Манекен», выбор запоминается. Данные MakeHuman (~2 МБ)
  грузятся в фоне, до загрузки показывается манекен.
- Справа вкладка «Параметры»: пол, возраст, рост, вес, % жира и обхваты: грудь, талия, бёдра, плечо, бедро;
  шея, голень и запястье — необязательно (галочка «Указать: …»), иначе оцениваются по другим замерам и росту.
  У каждого — ползунок и поле, в поле можно писать с запятой. Производные значения (безжировая и жировая
  масса, ИМТ, талия/рост) только показываются.
- Вкладка «Гипотеза»: срок, калории в день, бытовая активность, кардио и силовые, целевой вес
  (необязательно). Результат — итог (жир, безжировая ткань, вода и гликоген по отдельности), предупреждения,
  таблица «было → станет», график веса по неделям.
- Профиль, гипотеза и выбранная модель хранятся в localStorage браузера. Поля профиля `Sex`, `Age`,
  `HeightCm`, `WeightKg` названы как в `UserProfile`. Если сохранённого профиля нет: мужчина 180 см, 78 кг,
  14 % жира.
- В правом нижнем углу вида — модель, число вершин, время построения сетки, передачи её в JS и проверки замеров.

### Модель MakeHuman (по умолчанию)

Реалистичная форма тела, которую процедурным манекеном не получить: базовая сетка MakeHuman hm08
(только тело — 13 380 вершин) и её таргеты. Используются только ассеты MakeHuman под **CC0 1.0** — сетка
и таргеты, переведённые в компактный бинарный файл `wwwroot/data/makehuman-hm08.bin` (источник, коммит
и команда пересборки — в `wwwroot/data/README.md`). Код MakeHuman (AGPL) не используется: загрузка,
подгонка и замер написаны заново в `BodyModel/MakeHuman`.

Как строится тело (`MakeHumanModel.cs`):

1. **Макро-таргеты** — пол, возраст, мускулатура, полнота. Мускулатура и полнота считаются по индексам
   безжировой и жировой массы (кг/м²) относительно типичных для пола; константы — оценки прототипа
   (`MakeHumanMapping.cs`). Расовые таргеты MakeHuman усредняются — внешность нейтральная.
2. **Масштаб под рост**, ступни на полу.
3. **Таргеты замеров** MakeHuman (грудь, талия, бёдра, плечо, бедро, шея, голень, запястье) подгоняют
   введённые обхваты с точностью 0,5 мм (тест: ≤ 1 %). Обхват меряется «лентой»: сечение сетки плоскостью
   на тех же уровнях, что у манекена (у рук, ног и шеи — поперёк сегмента, по суставам MakeHuman), длина —
   по выпуклой оболочке сечения, как у натянутой ленты. Необязательные обхваты, которые не указаны,
   не подгоняются.
4. **Слой мягких тканей.** Если подогнать одни обхваты, объём тела выходит на 6–15 % меньше, чем следует
   из веса и % жира: вес лежит не только там, где меряют. Поэтому поверх формы по всему телу кладётся
   равномерный слой (от −8 до +25 мм вдоль нормалей), подобранный так, чтобы объём сошёлся с весом
   (тест: ±3 %), и обхваты подгоняются заново. Толщина слоя видна на вкладке «Параметры»; если слоя
   не хватило — подсказка, что замеры и вес, скорее всего, не согласуются.

Пока ползунок движется, подгонка стартует с прошлого решения, а слой не пересчитывается: 20–35 мс
на сборку, 40–50 мс, если меняются пол, возраст, рост, вес или % жира (пересчитываются макро).
Через 150 мс после остановки — точная сборка со слоем под вес.

### Как устроен манекен

Запасной вариант (переключатель «Манекен»): не анатомия, а гладкий манекен, у которого обхваты на модели
совпадают с введёнными (тест: ≤ 1 %). Строится за 10–20 мс и служит эталоном для проверки замеров.

- **Высоты и длины** — доли роста по Drillis & Contini (в изложении Winter, «Biomechanics and Motor
  Control of Human Movement»): плечи 0,818·H, тазобедренный сустав 0,530·H, колено 0,285·H, плечо 0,186·H,
  предплечье 0,146·H, бедро 0,245·H, голень 0,246·H. Ширины плеч (0,259·H) и таза (0,191·H) задают
  положение суставов. Уровней талии, паха, ягодиц, низа груди, подмышек и шеи в этой таблице нет —
  их доли оценены и помечены в `Proportions.cs`.
- **Туловище** — эллиптические сечения на уровнях пах, ягодицы, талия, низ груди, грудь, подмышки, плечи,
  основание шеи. Для каждого уровня задано соотношение глубина/ширина (зависит от пола, а у талии —
  и от % жира); полуоси подбираются так, чтобы периметр по Рамануджану равнялся обхвату. Между уровнями —
  монотонная кубическая интерполяция (аналог Catmull-Rom без «перелётов»), 48 точек по окружности.
- **Руки, ноги, шея** — трубки с круглыми сечениями. Плечо и бедро — из ввода, голень и запястье — из ввода,
  если указаны; дельта, локоть, предплечье, колено, щиколотка и неуказанные голень с запястьем — производные
  от плеча, бедра и роста (`SectionShapes.cs`).
  Голова, кисти и стопы — суперэллипсоиды. Поза — A-поза, руки под 35° к вертикали.
- **Сетка** строится в C# (~19,6 тыс. вершин) и уходит в JS бинарно (`[JSImport]` + MemoryView).
  JS только рисует: three.js 0.186.1 лежит в `wwwroot/lib/three` и подключён через import map.
- **Объём** — сумма замкнутых частей по теореме о дивергенции минус их перекрытия (корни рук и ног внутри
  туловища и т. п.; перекрытия считаются сеткой точек).

### Проверка замеров

- Объём манекена сравнивается с объёмом из веса: плотность по Сири D = 495 / (%жира + 450) г/см³,
  объём = вес / D **плюс воздух в лёгких** (3,0 л у мужчин, 2,4 л у женщин). Сетка — внешний объём тела,
  а плотность по Сири считается без воздуха; без этой поправки любой манекен был бы на 3–5 % «толще» веса.
- Объём для проверки всегда берётся у манекена, в том числе когда на экране MakeHuman: у MakeHuman объём
  подгоняется под вес слоем мягких тканей, поэтому сравнивать его с весом бессмысленно.
- При расхождении больше 12 % — мягкая подсказка «замеры и вес плохо согласуются», не ошибка.
- Подсказки о неправдоподобных сочетаниях: талия больше груди при низком % жира, талия/рост против
  % жира, ИМТ против % жира, % жира ниже незаменимого, места замера бедра и плеча.

### Прогноз: модель и допущения

Расчёт по неделям, все константы с источниками — в `ForecastConstants.cs`.

- **Расход** = БМР по Миффлину — Сан Жеору (пересчитывается от текущего веса каждую неделю) × коэффициент
  бытовой активности + активные ккал тренировок. Кардио считает калькулятор (`EnergyCalculator`) тоже
  от текущего веса; силовая — 3,5 MET × 1 ч (Compendium of Physical Activities, 2011). Берутся только
  активные ккал: БМР за время тренировки уже входит в «БМР × коэффициент».
- **Энергия тканей** (Hall et al., Lancet, 2011): жир 9400 ккал/кг, безжировая масса 1800 ккал/кг.
- **Дефицит:** доля безжировой массы в потере — по правилу Форбса (Forbes, 2000; Hall, Br J Nutr, 2007):
  10,4 / (10,4 + жировая масса, кг), пересчёт каждую неделю. У полного человека почти всё уходит из жира,
  у худощавого — всё больше из мышц. Силовые тренировки уменьшают эту долю вчетверо (×0,25): что упражнения
  сильно сберегают мышцы при дефиците, показывают обзоры (например, Weinheimer et al., Nutr Rev, 2010),
  а сам коэффициент — оценка прототипа. Жир не опускается ниже незаменимого (3 % / 12 %).
- **Вода и гликоген:** запас ≈ 1,5 % безжировой массы (гликоген хранится с водой примерно 1 : 3).
  При дефиците он уходит за 1–2 недели (60 % оставшейся разницы в неделю), при профиците пополняется
  наполовину; полностью — при балансе от 1000 ккал/день, при меньшем пропорционально. Килограмм запаса
  даёт ~1000 ккал и покрывает часть дефицита. Поэтому в первые недели вес на весах падает быстрее, чем уходит
  жир. Вода и гликоген входят в вес, но не в обхваты; в результатах они показаны отдельной строкой.
- **Профицит:** мышцы растут только с силовыми и не быстрее потолка по стажу — нижняя граница диапазонов
  Алана Арагона: новичок 1 %, средний 0,5 %, опытный 0,25 % веса в месяц, у женщин вдвое меньше.
  (Его диапазоны — темпы общего набора веса, а не чистых мышц, поэтому взята нижняя граница.) Остаток — жир.
- **Обхваты:** изменение жира и мышц раскладывается по регионам (живот, грудь, ягодицы, ноги, руки, шея)
  по долям, зависящим от пола, и переводится в обхват через цилиндр V = C²·L/(4π) с неизменной длиной L.
  L берётся из раскладки манекена, поэтому объём модели-прогноза сходится с прогнозным весом.
  Доли одни и те же при наборе и потере — **локального жиросжигания нет**, «убрать только живот» нельзя.
  Указанная голень меняется пропорционально бедру, запястье (кости и сухожилия) не меняется.
- **Предупреждения:** темп похудения больше 1 % веса в неделю, калории ниже БМР, цель недостижима
  за срок, профицит без силовых, жир к концу срока ниже ~8 % (мужчины) / ~15 % (женщины).

Что модель **не** учитывает: адаптацию обмена сверх снижения веса, колебания воды (соль, цикл, стресс),
возраст в скорости набора мышц, гормоны и реальное соблюдение плана. Поэтому в интерфейсе — подпись
«грубая оценка, а не обещание».
