# Калькулятор тренировок

Оценка расхода калорий при ходьбе и беге — на дорожке и на улице.
Нужна как независимая проверка цифр Apple Watch, которые на дорожке с уклоном сильно ошибаются.

## Запуск

Окно с пошаговым мастером (Windows, macOS, Linux):

```bash
dotnet run --project src/WorkoutCalculator.Desktop
```

Консольная версия:

```bash
dotnet run --project src/WorkoutCalculator.Cli
```

3D-модель тела по замерам (прототип, открывается в браузере):

```bash
dotnet run --project src/WorkoutCalculator.Body3D
```

Приложение поднимется на http://localhost:5256 и откроет браузер. Нужен только .NET 10 SDK:
дополнительные рабочие нагрузки (`wasm-tools`) и Node.js не нужны, three.js лежит в репозитории.

Тесты всего решения:

```bash
dotnet build WorkoutCalculator.sln
dotnet test WorkoutCalculator.sln
```

Или откройте `WorkoutCalculator.sln` в Visual Studio / Rider.
Проекты настроены на .NET 10. Body3D использует возможности Blazor из .NET 10, поэтому решению целиком нужен
.NET 10 SDK; для одних Core, Cli и Desktop можно заменить `net10.0` на `net8.0` в `Directory.Build.props`.

## Структура

| Проект | Что внутри |
|---|---|
| `WorkoutCalculator.Core` | Формулы, модели, разбор ввода, сохранение профиля. Без интерфейса. |
| `WorkoutCalculator.Desktop` | Окно на Avalonia: профиль → тренировка → параметры → часы → результат. |
| `WorkoutCalculator.Cli` | Та же логика в консоли. |
| `WorkoutCalculator.BodyModel` | Модель тела без интерфейса: антропометрия, тело MakeHuman и манекен по замерам, объём, проверки замеров, прогноз. |
| `WorkoutCalculator.Body3D` | Прототип в браузере: Blazor WebAssembly + three.js, без бэкенда. |
| `tools/WorkoutCalculator.MakeHumanImport` | Конвертер данных MakeHuman в `wwwroot/data/makehuman-hm08.bin`. Нужен только для пересборки данных. |
| `tools/WorkoutCalculator.AnsurFit` | Подбор коэффициентов `AnsurGirths`, сверка уровней `Proportions` и проверка обеих моделей на людях из открытых данных ANSUR II. |
| `tests/WorkoutCalculator.Tests` | xUnit: эталонные расчёты калорий, пропорции, манекен, тело MakeHuman, проверки, прогноз. |

## Что вводится

- **Профиль** (сохраняется между запусками, общий для окна и консоли): пол, возраст, рост, вес; необязательно — пульс покоя и VO2max.
- **Дорожка:** длительность, скорость, уклон (если они менялись по ходу — несколько отрезков), поручни, дистанция с табло для сверки.
- **Улица:** дистанция, время, набор высоты, покрытие.
- **Часы:** средний пульс, активные и общие ккал, дистанция — для сравнения.

Время можно вводить как `30`, `30,5` или `30:23`; дробные числа — через запятую или точку.

## Методы расчёта

| Метод | На чём основан | Источник |
|---|---|---|
| ACSM | скорость, уклон, время | ACSM's Guidelines for Exercise Testing and Prescription |
| Минетти | уклон, дистанция (учитывает спуск) | Minetti et al., J Appl Physiol, 2002 |
| Кейтел | пульс, вес, возраст, пол | Keytel et al., J Sports Sci, 2005 |

Итог — среднее по методам. Пульсовая оценка исключается из итога, если на долгой тренировке
она сильно выше механической (дрейф пульса) или пульс ниже 90.

Дополнительно: базовый обмен — Миффлин — Сан Жеор, максимальный пульс — Танака,
сопротивление воздуха при беге на улице — +1% уклона (Jones & Doust, 1996),
поручни — −20% к механическим методам.

Результаты — оценка, а не медицинское измерение.

## 3D-модель тела (прототип)

Тело строится по замерам — на основе MakeHuman или процедурным манекеном, — а режим гипотез показывает,
как оно может измениться за N недель при заданном питании и тренировках. Это проверка идеи,
а не финальный продукт.

### Интерфейс

- Слева 3D-вид: вращение мышью, зум колесом, кнопки «Спереди», «Сбоку», «Сзади», «Сброс камеры».
  Режимы «Сейчас», «Прогноз», «Сравнение». В сравнении текущее тело — светящийся контур поверх прогноза:
  видно, где тело уменьшится (контур снаружи) и где вырастет (контур уходит внутрь). Галочка «рядом»
  ставит модели бок о бок.
- Сверху переключатель модели «MakeHuman / Манекен», выбор запоминается. Данные MakeHuman (~2 МБ)
  грузятся в фоне, до загрузки показывается манекен.
- Галочка «ленты замеров» в левом нижнем углу показывает на теле, где меряется каждый обхват; лента
  обхвата подсвечивается оранжевым и без галочки — когда мышь над его полем или поле в фокусе.
- Справа вкладка «Параметры»: пол, возраст, рост, вес, % жира и обхваты: грудь, талия, бёдра, плечо, бедро;
  шея, голень и запястье — необязательно (галочка «Указать: …»), иначе оцениваются по данным ANSUR II.
  У каждого — ползунок и поле, в поле можно писать с запятой. Под % жира — оценка по обхватам (формула
  ВМС США) с кнопкой «Подставить»; без обхвата шеи формула не работает. Производные значения (безжировая
  и жировая масса, ИМТ, талия/рост) только показываются.
- Вкладка «Гипотеза»: срок, калории в день, бытовая активность, кардио и силовые, целевой вес
  (необязательно). Результат — итог (жир, безжировая ткань, вода и гликоген по отдельности, насколько
  подстроится обмен), предупреждения, таблица «было → станет», график веса по неделям.
- **Несколько гипотез** — до 5, каждая под своим названием. «+ Копия» добавляет вариант выбранной гипотезы,
  название меняется в поле «Название», удаление — с подтверждением. Кнопки «Сохранить» нет: изменения
  сохраняются сразу. Редактор и 3D-вид показывают выбранную гипотезу; выбрать её можно чипом вверху вкладки,
  заголовком столбца в сравнении, легендой графика или списком в 3D-виде (в режимах «Прогноз» и «Сравнение»).
  Таблица «Сравнение гипотез» показывает план (срок, питание, кардио, силовые, средний баланс) и итог к концу
  срока (вес, % жира, жир, безжировая ткань, обхваты, число предупреждений). На графике веса у каждой гипотезы
  своя линия, подсказка при наведении показывает все линии сразу. Цвет закреплён за гипотезой и не меняется,
  когда соседние удаляют. Соседние цвета палитры различимы и при дальтонизме (проверено по ΔE в OKLab
  с имитацией протанопии и дейтеранопии), контраст с фоном — не меньше 3:1.
- Профиль, гипотезы и выбранная модель хранятся в localStorage браузера. Поля профиля `Sex`, `Age`,
  `HeightCm`, `WeightKg` названы как в `UserProfile`. Если сохранённого профиля нет: мужчина 180 см, 78 кг,
  14 % жира. Гипотеза, сохранённая прежней версией (одна, без названия), открывается как «План 1».
- В правом нижнем углу вида — модель, число вершин, время построения сетки, передачи её в JS и проверки замеров.

### Модель MakeHuman (по умолчанию)

Реалистичная форма тела, которую процедурным манекеном не получить: базовая сетка MakeHuman hm08
(только тело — 13 380 вершин) и её таргеты. Используются только ассеты MakeHuman под **CC0 1.0** — сетка
и таргеты, переведённые в компактный бинарный файл `wwwroot/data/makehuman-hm08.bin` (источник, коммит
и команда пересборки — в `wwwroot/data/README.md`). Код MakeHuman (AGPL) не используется: загрузка,
подгонка и замер написаны заново в `BodyModel/MakeHuman`.

Как строится тело (`MakeHumanModel.cs`):

1. **Макро-таргеты** — пол, возраст, мускулатура, полнота. Мускулатура и полнота считаются по индексам
   безжировой и жировой массы (кг/м²) относительно типичных для пола; константы — оценки прототипа
   (`MakeHumanMapping.cs`). Расовые таргеты MakeHuman усредняются — внешность нейтральная.
2. **Масштаб под рост**, ступни на полу.
3. **Таргеты замеров** MakeHuman подгоняют обхваты на 10 уровнях с точностью 0,5 мм: введённые (тест: ≤ 1 %),
   а где замеров нет — оценки ANSUR II (тест: ≤ 2 %): неуказанные шея, голень и запястье, а ещё низ бедра
   над коленом и щиколотка (таргеты knee-circ и ankle-circ). Без колена и щиколотки бедро полного человека
   «проваливалось» над коленом. Обхват меряется «лентой»: сечение сетки плоскостью на тех же уровнях, что
   у манекена (у рук, ног и шеи — поперёк сегмента, по суставам MakeHuman), длина — по выпуклой оболочке
   сечения, как у натянутой ленты. У части мужчин подмышки MakeHuman оказываются ниже уровня груди
   по ANSUR II, и плоскость груди задевает руки — тогда лента груди опускается шагами по 0,5 % роста,
   но не больше чем на 3 %. Вес таргета замера ограничен ±3: с прежним ±2 у 8 % мужчин ANSUR II
   не подгонялась талия.
4. **Слой мягких тканей.** Даже с подогнанными обхватами тело MakeHuman выходит на 6–7 % меньше по объёму,
   чем следует из веса и % жира, у полных — на 11–13 %. Поэтому поверх формы кладётся слой вдоль нормалей,
   подобранный так, чтобы объём сошёлся с весом (тест: ±3 %), и обхваты подгоняются заново. Слой лежит
   по зонам тела (веса скелета MakeHuman, тоже CC0; коэффициенты — `SoftTissue.cs`): полностью на животе,
   боках, верхе спины и ягодицах, тоньше на руках и голенях, почти нет на кистях, стопах и лице. На бёдрах
   его нет: там таргеты замеров снимают слой целиком, и он только портил форму. На шее слой гасится по доле
   зоны шеи у вершины, иначе он затекал с плеч и тонкую шею нельзя было подогнать. Раньше слой был
   равномерным, и у полных профилей кисти становились «варежками», а лицо — раздутым.
   Толщина слоя (от −15 до +45 мм в самой толстой зоне) видна на вкладке «Параметры». Подбирается она
   за 1–3 перестройки тела. После слоя таргеты снова подгоняют обхваты и снимают бо́льшую часть добавленного
   объёма: остаётся около 0,28 «площади слоя × толщину» (у людей ANSUR II — от 0,1 до 0,4). С этой долей
   делается первый шаг, дальше — секущая по измеренному наклону, если он правдоподобен. Для очень больших
   размеров (талия больше ~130 см) формы MakeHuman не хватает: подсказка говорит, на сколько модель
   меньше, чем по весу, — это предел модели, а не ошибка в замерах.

**Проверка на людях ANSUR II** (`AnsurFit --validate`, по 300 человек каждого пола, ниже). Введённые
обхваты не подгоняются у 3,3 % мужчин и ни у одной женщины (до исправлений шага 4 — у 10,7 % и 2,7 %).
Все такие мужчины полные (ИМТ 30–41): талия или бедро выходят на 1–6 % меньше введённых, у одного шея —
на 4 % больше, и на экране об этом есть подсказка. Слой у 90 % людей — от −15 до +29 мм у мужчин и от −12
до +26 мм у женщин. Объём сходится с весом в пределах ±3 % у 96 % мужчин и 99 % женщин. Остальным нужен
слой тоньше нижнего предела: форма MakeHuman с их обхватами объёмнее тела, чаще у полных. Если утончать
слой дальше, таргеты замеров не успевают вернуть талию и бёдра. Замеры от этого не страдают — их
проверяет манекен.

Пока ползунок обхвата движется, подгонка стартует с прошлого решения, а слой не пересчитывается: ~20 мс
на сборку, 45–55 мс, если меняются пол, возраст, рост, вес или % жира (пересчитываются макро). Через
150 мс после остановки — точная сборка со слоем под вес, ~150 мс. С лентами замеров — ещё ~20 мс.

### Как устроен манекен

Запасной вариант (переключатель «Манекен»): не анатомия, а гладкий манекен, у которого обхваты на модели
совпадают с введёнными (тест: ≤ 1 %). Строится за 10–20 мс и служит эталоном для проверки замеров.

- **Высоты и длины** — доли роста по Drillis & Contini (в изложении Winter, «Biomechanics and Motor
  Control of Human Movement»): плечи 0,818·H, тазобедренный сустав 0,530·H, колено 0,285·H, плечо 0,186·H,
  предплечье 0,146·H, бедро 0,245·H, голень 0,246·H. Ширины плеч (0,259·H) и таза (0,191·H) задают
  положение суставов. Уровни груди, пупка, ягодиц, промежности и подмышек — средние ANSUR II (ниже);
  остальных уровней нет и там, их доли оценены и помечены в `Proportions.cs`.
- **Туловище** — эллиптические сечения на уровнях пах, ягодицы, талия, низ груди, грудь, подмышки, плечи,
  основание шеи. Для каждого уровня задано соотношение глубина/ширина. Оно зависит от пола, а у груди,
  низа груди, талии и бёдер ещё и от ИМТ: у полных сечения круглее, с тем же наклоном, что у отношения
  глубины к ширине у людей ANSUR II (+0,9…1,3 % на единицу ИМТ). Полуоси подбираются так, чтобы периметр
  по Рамануджану равнялся обхвату. Между уровнями — монотонная кубическая интерполяция (аналог Catmull-Rom
  без «перелётов»), 48 точек по окружности.
- **Руки, ноги, шея** — трубки с круглыми сечениями. Плечо и бедро — из ввода, голень и запястье — из ввода,
  если указаны. Предплечье, низ бедра, щиколотка и неуказанные голень, запястье и шея — по ANSUR II
  (`AnsurGirths.cs`); дельта, локоть, середина бедра — оценки (`SectionShapes.cs`).
  Голова, кисти и стопы — суперэллипсоиды. Поза — A-поза, руки под 35° к вертикали.
- **Сетка** строится в C# (~19,6 тыс. вершин) и уходит в JS бинарно (`[JSImport]` + MemoryView).
  JS только рисует: three.js 0.186.1 лежит в `wwwroot/lib/three` и подключён через import map.
- **Объём** — сумма замкнутых частей по теореме о дивергенции минус их перекрытия (корни рук и ног внутри
  туловища и т. п.; перекрытия считаются сеткой точек). Пересечение бёдер между собой не вычитается:
  у полных бёдра сплющиваются друг о друга, но ткань никуда не девается.

### Пропорции по данным ANSUR II

ANSUR II — антропометрическое обследование армии США 2010–2012 гг., открытые данные: 4082 мужчины
и 1986 женщин, 93 замера. Выборка военная — моложе и спортивнее населения в среднем, но вес от 36 до 144 кг.

- **Обхваты, которых нет в замерах** (`AnsurGirths.cs`) — линейные регрессии по росту и весу, для голени
  и низа бедра — ещё по обхвату бедра. Против прежних оценок:

  | Обхват | Было: сдвиг / ошибка | Стало: ошибка |
  |---|---|---|
  | Голень, женщины | +2,4 / 3,1 см | 1,7 см |
  | Голень, мужчины | +1,7 / 2,5 см | 1,6 см |
  | Щиколотка | −1,2…−1,4 / 1,7–1,8 см | 1,0–1,2 см |
  | Запястье, шея, низ бедра | ошибка 0,7–2,0 см | на 10–25 % точнее |

- **Уровни** груди, пупка, ягодиц, промежности и подмышек — средние ANSUR II. Сильнее всего поправился
  уровень груди у мужчин: 0,735 роста вместо 0,720 (на 2,7 см выше).
- **Пересчёт.** Сами данные в репозиторий не входят. Скачайте `ANSUR II MALE Public.csv` и
  `ANSUR II FEMALE Public.csv` (например, с [официальной страницы](https://ph.health.mil/topics/workplacehealth/ergo/Pages/Anthropometric-Database.aspx))
  и запустите:

  ```bash
  dotnet run --project tools/WorkoutCalculator.AnsurFit -- "ANSUR II MALE Public.csv" "ANSUR II FEMALE Public.csv"
  ```

  Утилита печатает коэффициенты и уровни и завершается с ошибкой, если таблица в коде с ними не совпадает.
- **Проверка моделей на людях.** С флагом `--validate` (в конце команды выше) утилита строит тело каждого
  человека по его росту, весу и обхватам: % жира — по формуле ВМС США, бицепс в ANSUR меряют напряжённым,
  расслабленный считается на 1,5 см меньше. Манекен проверяется на всех (6059 человек), MakeHuman — на
  выборке по 300 человек каждого пола. Печатается отклонение объёма от объёма по весу по группам ИМТ, толщина
  слоя MakeHuman и какие обхваты не подогнались. Поправка объёма манекена по ИМТ (ниже) подбирается заново
  и сверяется с кодом: при расхождении утилита завершается с ошибкой. Без данных MakeHuman проверяется
  только манекен.

### Проверка замеров

- Объём манекена сравнивается с объёмом из веса: плотность по Сири D = 495 / (%жира + 450) г/см³,
  объём = вес / D **плюс воздух в лёгких** (3,0 л у мужчин, 2,4 л у женщин). Сетка — внешний объём тела,
  а плотность по Сири считается без воздуха; без этой поправки любой манекен был бы на 3–5 % «толще» веса.
- Объём для проверки всегда берётся у манекена, в том числе когда на экране MakeHuman: у MakeHuman объём
  подгоняется под вес слоем мягких тканей, поэтому сравнивать его с весом бессмысленно.
- **Поправка по ИМТ.** Даже у реальных людей манекен по их обхватам выходит то объёмнее, то меньше тела:
  у худых мужчин на ~5 % больше объёма по весу, у полных женщин на ~4 % меньше. Вероятные причины — живот
  между уровнями замеров и эллипс вместо настоящего сечения. Поэтому объём манекена делится на
  1 + a + b·(ИМТ − 25); a и b подобраны на людях ANSUR II (`ConsistencyChecker.MannequinBias`). С поправкой
  среднее отклонение в каждой группе ИМТ — от −0,2 до +0,6 %, разброс — 2,2 % у мужчин и 2,5 % у женщин.
- При расхождении больше 8 % (около трёх стандартных отклонений) — мягкая подсказка «замеры и вес плохо
  согласуются», не ошибка. У людей ANSUR II она срабатывает у 0–0,1 %, так что почти всегда это ошибка
  ввода, а не особенность фигуры. Свой % жира с весов или калипера тоже ошибается на несколько процентов.
- **% жира по обхватам** — формула ВМС США (Hodgdon & Beckett, 1984): у мужчин по шее и талии на уровне
  пупка, у женщин ещё по бёдрам, талия — в самом узком месте. Её ошибка — 3–4 % жира; если введённый
  % отличается от оценки больше чем на 7 %, появляется подсказка перепроверить. Без шеи формула не считается.
- Подсказки о неправдоподобных сочетаниях: талия больше груди при низком % жира, талия/рост против
  % жира, ИМТ против % жира, % жира ниже незаменимого, места замера бедра и плеча.

### Прогноз: модель и допущения

Расчёт по неделям, все константы с источниками — в `ForecastConstants.cs`.

- **Расход** = БМР по Миффлину — Сан Жеору (пересчитывается от текущего веса каждую неделю) × коэффициент
  бытовой активности + активные ккал тренировок. Кардио считает калькулятор (`EnergyCalculator`) тоже
  от текущего веса; силовая — 3,5 MET × 1 ч (Compendium of Physical Activities, 2011). Берутся только
  активные ккал: БМР за время тренировки уже входит в «БМР × коэффициент».
- **Адаптация обмена** (Hall et al., Lancet, 2011): если питание отличается от поддержания в начале плана,
  расход сразу меняется на 10 % от разницы (термический эффект пищи) и ещё на 14 % — постепенно,
  с постоянной времени 14 дней (адаптивный термогенез). Разница считается по всему дефициту или профициту
  плана, даже если его даёт кардио (у Холла — только питание; так проще и осторожнее). При −500 ккал
  в день вес за 12 недель уходит примерно на 20 % медленнее, чем без адаптации.
- **Энергия тканей** (Hall et al., Lancet, 2011): жир 9400 ккал/кг, безжировая масса 1800 ккал/кг.
- **Дефицит:** доля безжировой массы в потере — по правилу Форбса (Forbes, 2000; Hall, Br J Nutr, 2007):
  10,4 / (10,4 + жировая масса, кг), пересчёт каждую неделю. У полного человека почти всё уходит из жира,
  у худощавого — всё больше из мышц. Силовые тренировки уменьшают эту долю вчетверо (×0,25): что упражнения
  сильно сберегают мышцы при дефиците, показывают обзоры (например, Weinheimer et al., Nutr Rev, 2010),
  а сам коэффициент — оценка прототипа. Жир не опускается ниже незаменимого (3 % / 12 %).
- **Вода и гликоген:** запас ≈ 1,5 % безжировой массы (гликоген хранится с водой примерно 1 : 3).
  При дефиците он уходит за 1–2 недели (60 % оставшейся разницы в неделю), при профиците пополняется
  наполовину; полностью — при балансе от 1000 ккал/день, при меньшем пропорционально. Килограмм запаса
  даёт ~1000 ккал и покрывает часть дефицита. Поэтому в первые недели вес на весах падает быстрее, чем уходит
  жир. Вода и гликоген входят в вес, но не в обхваты; в результатах они показаны отдельной строкой.
- **Профицит:** мышцы растут только с силовыми и не быстрее потолка по стажу — нижняя граница диапазонов
  Алана Арагона: новичок 1 %, средний 0,5 %, опытный 0,25 % веса в месяц, у женщин вдвое меньше.
  (Его диапазоны — темпы общего набора веса, а не чистых мышц, поэтому взята нижняя граница.) Остаток — жир.
- **Обхваты:** изменение жира и мышц раскладывается по регионам (живот, грудь, ягодицы, ноги, руки, шея)
  по долям, зависящим от пола, и переводится в обхват через цилиндр V = C²·L/(4π) с неизменной длиной L.
  L берётся из раскладки манекена, поэтому объём модели-прогноза сходится с прогнозным весом.
  Доли одни и те же при наборе и потере — **локального жиросжигания нет**, «убрать только живот» нельзя.
  Указанная голень меняется пропорционально бедру, запястье (кости и сухожилия) не меняется.
- **Предупреждения:** темп похудения больше 1 % веса в неделю, калории ниже БМР, цель недостижима
  за срок, профицит без силовых, жир к концу срока ниже ~8 % (мужчины) / ~15 % (женщины).

Что модель **не** учитывает: что обмен у разных людей подстраивается по-разному (в модели — средние
коэффициенты Холла), колебания воды (соль, цикл, стресс), возраст в скорости набора мышц, гормоны
и реальное соблюдение плана. Поэтому в интерфейсе — подпись «грубая оценка, а не обещание».
