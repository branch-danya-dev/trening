## Observed problems and presentation decisions

Owner review, 2026-10-14: the long Progress block pushed the avatar away; forecast shortcuts could show a legacy scenario; photo editors were recreated on navigation; animation rotations used incompatible rest axes. The corrective workspace keeps 3D in the window, scrolls only the task pane, binds forecast shortcuts to saved observed endpoints, retains one lazy photo editor, and corrects exercise rotations in presentation space. The requested local photo-surface mode and independent dated before/after materials are documented in [UI_REDESIGN](UI_REDESIGN.md). They do not write measurements or alter frozen predictions.

| State / task | Baseline problem | Keep / change / consumer wording |
|---|---|---|
| New user | Required fields and optional measurements look similar; progress is text only | Keep eight durable stages, add progress strip and explicit optional guidance; unknown remains valid |
| Avatar draft / correction | Dense controls compete with viewport, model provider is global navigation chrome | Keep semantic controls and live preview; large viewport, group controls, move provider to Advanced |
| Locked avatar | Workout/program/calibration prose competes with actual body parameters | Make body, update date, facts, New measurement primary; corrections secondary; revision metadata disclosed |
| Empty day | Full calendar occupies first mobile screen, plan appears above facts | Date/state, quick actions, factual summary, activity, nutrition, plan comparison, close; calendar disclosed |
| Populated day | Nutrition and activity share long unstructured stack; repeated heatmaps | Keep real events/source guards, clear section headings, muscle loads as drill-down |
| Partial nutrition | Short “Partial” is ambiguous; unknown values are verbose | “Рацион заполнен частично”; never convert missing macros or intake to zero |
| Complete nutrition | Frozen completeness matters but gets lost in paragraph | Keep explicit full-intake confirmation and immutable closure; visible coverage label |
| Preliminary hypothesis | Dense assumptions bury the 14/30-day endpoint | Maturity and endpoint first; assumptions disclosed; frozen after issue |
| Insufficient / eligible preview | Missing data looks like a technical rejection | Closed days X/3 and complete nutrition X/3; actionable explanation; preview never persists |
| Active / awaiting | Alternate manual scenario and previous-fact selector compete with intended next action | Observed hypothesis primary; “Пройти контрольный замер” primary when eligible; existing measurement secondary |
| Evaluated / expired | Technical provenance and calibration text dominate result | Predicted/actual/difference/date/source first; no accuracy percentage; expiry remains explicit |
| Accepted / rejected CheckIn | Facts saved vs model update needs interpretation | State separately whether measurements saved and avatar updated; failed photos do not discard allowed manual facts |
| Geometry eligible / unsupported | Local deformation reads as another forecasting system | Disclosed “Геометрическая визуализация”; local, not AI or a future photograph; exact reason and 3D fallback |
| Profile / quota warning | Validation diagnostics longer than ordinary settings; health service has no normal screen | Group personal data, tracking, privacy, data; show StorageHealth; diagnostics collapsed |
| Large history (1000 days) | Long factual/history lists and expensive full-store boundaries | Keep existing services and bounded caches; lazy details; no storage rewrite; compare same archive before/after |
